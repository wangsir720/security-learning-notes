# Day 3｜等保 2.0 从条文到落地清单

一句话结论：等保不是一份文档，而是客户需要保留和验证的通信、边界、计算和审计证据链。

## 1. 三类重点

| 层面 | 关注点 | 常见措施 |
|---|---|---|
| 安全通信网络 | 通信完整性和保密性 | 分区、加密、链路冗余 |
| 安全区域边界 | 边界访问和入侵防范 | 防火墙、IPS、WAF |
| 安全计算环境 | 主机、应用和数据安全 | EDR、权限、补丁、审计 |

## 2. 从条文翻译成采购与配置清单

| 要求 | 需要什么 | 需要留什么证据 |
|---|---|---|
| 访问控制 | 网络分区、最小权限 | 策略截图、审批记录 |
| 入侵防范 | IPS、WAF、EDR | 告警记录、处置单 |
| 恶意代码防范 | EDR、病毒防护 | 扫描报告 |
| 安全审计 | 日志集中、时间同步 | 日志留存、审计报表 |
| 数据完整性 | 备份、校验、加密 | 备份记录、恢复演练 |

## 3. 自查表

- [ ] 资产清单是否完整；
- [ ] 核心系统是否分区；
- [ ] 日志是否集中；
- [ ] 告警是否有责任人；
- [ ] 处置结果是否留痕；
- [ ] 报表是否可导出。

## 4. 与告警分诊 POC 的关系

POC 的 HTML/Markdown 报告和风险分级，可以直接作为“告警处置与审计留痕”的演示材料。
